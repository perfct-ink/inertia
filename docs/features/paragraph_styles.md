# Paragraph styles

## What it does
The document toolbar has a "Paragraph style" menu. It shows the style of the block the cursor is in and applies another to it. Built-in styles: **Title**, **Subtitle**, **Heading 1**, **Heading 2**, **Heading 3**, **Body**, **Quote**, **Caption** and **Monospace**. Headings are real heading nodes (levels 1 to 3, and so appear in the outline); the others are paragraphs with a `style` attribute (title, subtitle, quote, caption, monospace; absent or body is a plain paragraph) with their own look in `ProseMirror.scss`. The menu shows "Style" when the cursor is in something that isn't a styled paragraph or heading 1 to 3 (lists, code blocks, deeper headings). The document's own title is still its first heading.

### Your own styles
The same menu has **New style…** and, once you have a style, a **My styles** group and **Manage styles…**.

- **Create.** New style… opens a form that starts from the paragraph under the cursor: its built-in style as the base, or, in a paragraph that already has a custom style, that style's formatting. Name it (up to 40 characters, not a built-in label, not one of your own names, up to 50 styles), then set any of font (sans-serif, serif, monospace), size (12 to 48 px), weight, line spacing, alignment and colour; "Default" leaves a property to the base style. Saving adds it to My styles and applies it to the paragraph. The editor has no per-paragraph font, size or colour controls, so "the current paragraph's formatting" is its style's formatting; a heading starts from Body.
- **Everywhere.** A style belongs to your account, not to a Space or a document: it is listed in the menu of every document you edit, in every Space. Nobody else sees your list.
- **Edit or delete.** Manage styles… lists your styles with Edit (the same form, with the style's values) and Delete (asks first). Editing or deleting changes the style, then the documents you edit follow (below).
- **Looks the same to everyone.** A paragraph in a custom style stores three attributes: `style` = `custom-<id>`, `styleName` and `styleProps` (a JSON string `{owner, base, properties}`, the formatting resolved when the style was last applied or refreshed). It is drawn from that copy alone (`data-style-base` for the built-in look it builds on, plus inline CSS for the formatting), so collaborators, people with other styles and people with no styles all see the same paragraph, and nothing needs fetching to draw it. Only **the owner's** menu lists the style; in someone else's menu the paragraph just shows the style's name as the current value (it can't be chosen again from their menu).
- **Edit updates documents, by the owner's editor.** The server never touches documents (they live in the collaboration server), so the owner's browser does it: `useCustomStyleSync` runs in every open document. When the paragraphs' copies of one of *your* styles differ from your styles, it fetches your list fresh and rewrites the copies (name and formatting); when the style no longer exists and the copy names you as its owner, the paragraph becomes Body. This happens when you open a document, when your style list changes (after an edit or delete) and as the document changes. The rewrite is one transaction kept out of undo history. People you share a document with keep seeing the last copy until you next open that document in an editor; a style someone else owns is never touched by your editor.
- **Safety.** The copy comes from a document anyone can edit, so every value is checked when read (`readSnapshot`): only the allowed fonts, sizes, weights, `#rrggbb` colours, spacings and alignments, a known base, and a copy longer than 600 characters is ignored. Nothing else reaches the page.

## API and models
- Custom styles: model `ParagraphStyle` (`backend/app/models/paragraph_style.rb`, table `paragraph_styles`: `user_id`, `name`, `base`, `properties` JSON) with the checks mirrored in `frontend/src/data/customParagraphStyle.ts` (KEEP IN SYNC).
- Endpoints, all for the signed-in person's own styles and not scoped to a Space: `GET /api/v1/paragraph_styles`, `POST /api/v1/paragraph_styles`, `PATCH /api/v1/paragraph_styles/:id`, `DELETE /api/v1/paragraph_styles/:id`. Another person's id is a 404. A rule broken (taken name, built-in name, bad value, more than 50) is a 422 with `errors`.
- Documents: styles are stored in the document content as the paragraph's attributes `style`, `styleName`, `styleProps`. `StyledParagraph` (`frontend/src/extensions/StyledParagraph.ts`) adds them and draws a custom style from them, mirrored in `collab-server/src/schema.ts` so collaboration keeps them. The built-in list and `styleOfBlock` are in `frontend/src/data/paragraphStyle.ts`; the rules for the copy (apply, read, draw, refresh) are in `data/customParagraphStyle.ts`; editor commands in `util/customParagraphStyleCommand.ts`; the menu is `components/ParagraphStylePicker.tsx`, the forms `CustomStyleDialog.tsx` and `CustomStylesDialog.tsx`, the API `frontend/src/api/paragraphStyles.ts`.

## Who can view and change
- Built-in styles: anyone who can edit the document, shared with everyone who opens it.
- Custom styles: the list and the styles are the owner's alone (API: signed-in user, own rows only). A paragraph in a custom style is document content, so everyone who opens the document sees its name and formatting (but not the owner's other styles), and anyone who can edit the document can change that paragraph's style like any other paragraph. Only the owner's editor refreshes a style's copies.

## Known limits
- The collab server must be deployed with the frontend: an older collab server drops `styleName` and `styleProps` from the documents it saves, so custom styles would lose their look. Deploy the collab server together with the frontend (`collab-server/src/schema.ts` changed).
- No keyboard shortcuts for the new styles (`paragraph-style-shortcuts`) or for custom styles (`paragraph-style-keystrokes`).
- Edits and deletes reach a document only when its owner opens it in an editor (chosen so a shared document never changes under people who don't own the style, and so the document, not the server, stays the one place the look is stored). Until then collaborators see the last copy, even of a deleted style; there is no "restyle every document now".
- A heading can't carry a custom style (headings are heading nodes); choosing a custom style on a heading turns it into a paragraph.
- Pasting a custom-style paragraph from another document or person brings its copy along, so it looks the same; it is refreshed when the owner next opens the document.
- Applying a style to several blocks at once, and styles inside list items or table cells, were not tried. Existing documents are unaffected (no `style` means body).
- The editor has no per-paragraph font, size or colour of its own, so a new style starts from the paragraph's built-in or custom style rather than from measured CSS.
- Heading buttons H1 to H5 remain beside the menu; H4 and H5 have no menu entry.
