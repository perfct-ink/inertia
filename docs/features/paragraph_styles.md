# Paragraph styles

## What it does
The document toolbar has a "Paragraph style" menu. It shows the style of the block the cursor is in and applies another to it. Built-in styles: **Title**, **Subtitle**, **Heading 1**, **Heading 2**, **Heading 3**, **Body**, **Quote**, **Caption** and **Monospace**. Headings are real heading nodes (levels 1 to 3, and so appear in the outline); the others are paragraphs with a `style` attribute (title, subtitle, quote, caption, monospace; absent or body is a plain paragraph) with their own look in `ProseMirror.scss`. The menu shows "Style" when the cursor is in something that isn't a styled paragraph or heading 1 to 3 (lists, code blocks, deeper headings). The document's own title is still its first heading.

**My styles.** A person can make their own styles. "New style…" at the bottom of the menu opens a form that starts from the paragraph the cursor is in: a name (up to 40 characters, not a built-in style's name, not one they already have), the built-in style it builds on (Body, Title, Subtitle, Quote, Caption or Monospace), and optional font (sans-serif, serif, monospace), size (12 to 48 px from a list), weight, line spacing, alignment and colour (a set of swatches). Anything left on "Default" comes from the base style. Saving applies the style to the paragraph, and the style appears under "My styles" in the menu of every document for that person only, other people don't see it in their menu. A paragraph in a custom style shows that style in the menu. A style someone else made that the open document uses is listed under "In this document" and can be applied there too; a paragraph whose style can't be read (deleted, or not loaded yet) shows "Style" and is drawn plain.

## API and models
- Built-in styles have no endpoint. They are stored in the document content as the paragraph's `style` attribute. `StyledParagraph` (`frontend/src/extensions/StyledParagraph.ts`) adds it, mirrored in `collab-server/src/schema.ts` so collaboration keeps it; the style list and `styleOfBlock` are in `frontend/src/data/paragraphStyle.ts`; the menu is `components/ParagraphStylePicker.tsx`.
- Custom styles: `paragraph_styles` table (`user_id`, `name`, `base`, `properties` json, unique per user and name ignoring case; migration `20261105060001`). `ParagraphStyle` (`backend/app/models/paragraph_style.rb`) validates the name, the base and each property (font, size 8 to 96, weight 400/500/600/700, `#rrggbb` colour, spacing 1.0 to 3.0, alignment), drops blank properties, and caps a person at 50. They belong to the person, not to a Space.
  - `GET /api/v1/paragraph_styles`: the signed-in person's own styles, oldest first. `POST /api/v1/paragraph_styles` (`{ paragraph_style: { name, base, properties } }`): 201, or 422 with `errors`. Formatting keys the model doesn't know are ignored. Any signed-in user; the Space header is ignored.
  - `GET /api/v1/documents/:document_id/paragraph_styles`: the custom styles the document's paragraphs refer to, whoever made them, for anyone who can open the document (404 otherwise). It reads the ids from the document's saved content (`ParagraphStyle.referenced_ids`), so it answers with those styles and no others; a style is otherwise private to its creator. The collaboration server saves content a few seconds behind the editor, so a style just applied by a collaborator can be missing for a moment; the browser asks again every five seconds, up to six times.
  - A paragraph that uses a style stores only the reference, `style: "custom-<id>"`: nothing else is in the document, and the collaboration server's schema is unchanged. The definition (`{ base, properties }`) is fetched, and `extensions/CustomParagraphStyle.ts` draws the paragraph from it as a node decoration (inline CSS plus `data-style-base`, with the base look in `ProseMirror.scss`). So editing a style restyles every paragraph that uses it, and a paragraph whose style can't be read is drawn plain. The decoration is not part of the document, so it is never saved or synced.
  - Because a definition comes from the server and may be someone else's, it is only drawn through `sanitizeProperties` and a known base (`styleDecoration` in `data/customParagraphStyle.ts`), which keep just the allowed properties and values; nothing else reaches the page's CSS or HTML. The allowed values exist in Ruby and TypeScript and must be kept in step.
  - Frontend: `data/customParagraphStyle.ts` (rules, CSS, the ids a document uses, name check), `api/paragraphStyles.ts`, `hooks/useDocumentCustomStyles.ts` (fetches the definitions and gives them to the editor), `components/CustomStyleDialog.tsx`.

## Who can view and change
Anyone who can edit the document applies any style to its paragraphs. A custom style is private to its creator's menu, but once a document uses it, everyone who can open that document can read its name and formatting (and apply it there) so they see the paragraph as its author does.

## Known limits
- A custom style can be created only: no editing, renaming or deleting (`docs/backlog/edit-or-delete-custom-style.md`), and no styles shared across people or global ones (`custom-styles-are-per-user-and-global.md`). Deleting one, once it exists, will leave paragraphs that refer to it drawn plain.
- A person with only a view link to a document (not built yet, `docs/backlog/custom-styles-in-shared-documents.md`) would see custom-styled paragraphs plain, because the lookup needs an account that can open the document.
- Every browser that opens a document using custom styles makes one extra request for them.
- Custom styles can't build on headings, only on the paragraph styles, and a style can't set an arbitrary colour, font size or font beyond the lists in the form.
- Keyboard shortcuts for the built-in styles are a separate task (`paragraph-style-shortcuts`); none for custom styles (`paragraph-style-keystrokes`).
- Heading buttons H1 to H5 remain beside the menu; H4 and H5 have no menu entry.
- Applying a style to several blocks at once, and styles inside list items or table cells, were not tried. Existing documents are unaffected (no `style` means body).
- The collab server must be deployed with the `style` attribute in its schema (built-in styles) before styled paragraphs sync. Custom styles add nothing to it: they use the same attribute.
