# Collection map view

## What it does
A Collection page has a **Grid | Map** switch under its title (shown once the Collection has a field). **Map** plots every record whose location field holds a place as a pin.

- **Location field.** Collections have no location type yet, so a place is a *text* field holding `latitude, longitude` as decimal degrees: `48.8584, 2.2945`. A space, `;`, brackets or a `geo:` prefix also work (`parseCoordinates` in `util/geo.ts`). Latitude must be within 90 and longitude within 180. The map opens on the text field with the most places in it, then one named like a location, then the first text field. With more than one text field, a "Location field" select in the side panel switches fields; with one, the select is hidden.
- **The map.** Pins fit the map when it opens. Drag to move it, use the zoom in/out buttons, or press the arrow keys and `+`/`-` with the map focused. "Show every pin" fits them again (it is disabled while the map is already fitted). Selecting a pin, on the map or in the side list, opens a details card on the map with the record's label, its coordinates, its other filled-in values and an "Open in OpenStreetMap" link; Esc (with the map focused) or the close button dismisses it. Choosing a record in the side list also centres the map on it. A record's label is its Name or Title text field, else its first filled-in text field, else `Record #id`.
- **Side panel.** "N of M records on the map", the list of pins, and, only when some records cannot be placed, "Not on the map (N)" naming the first 10 with what their location field says, and a hint to fix them in the Grid view. On a phone the panel sits below the map, which is as wide as the screen less its margins and about 60% of the screen high; from 1024px the panel sits to the right.
- **Empty states.** No text field: "Add a text field for each record's location". A text field but no coordinates: "No record has coordinates yet" (on a field that looks addresses up: "No record is on the map yet").
- **Addresses (optional, off until a provider is configured).** A text field can also hold an address or place name ("Eiffel Tower, Paris"). In the field form (Add field, or the field's name in the grid header), a text field shows **Look up addresses for the Map view**, only while the server has a geocoding provider (or on a field that already has it on, so it can be switched off). It carries a note that the field's text is sent to the place search service. When a record is saved, the server looks the text up and stores the result beside it: the matched name, latitude and longitude. The map then plots the record like one typed as coordinates, and the pin's details card shows the matched name. The text a person typed is never changed. Under each address in the grid, a lookup shows the matched name, or an error ("No place found for this text.", or "The place search is not available right now. Edit the text to try again."); the result is hidden while that cell is being edited, because it belongs to the old text. The map's "Not on the map" list shows the same reason beside each record. Editing the text drops the old place at once. Turning the option off removes the stored places and keeps the text. Text that is already coordinates is never looked up, nothing is looked up on page load, and the same text in a Space is looked up once (answers, and "no match", are remembered).
- **Base map.** By default the map is a latitude/longitude grid with labelled lines and makes **no request to any map server**. If the build sets `MAP_TILE_URL` (an https template with `{z}`, `{x}` and `{y}`), standard 256px tiles are drawn under the pins, with `MAP_TILE_ATTRIBUTION` shown in the corner; tiles are requested with `referrerpolicy="no-referrer"`. A template that is not https or lacks a placeholder is ignored. See [services.md](../services.md).
- Pins are 44px tap targets, the controls are 40px, and every colour comes from the theme tokens, so light and dark mode both work. Hover only changes colour, never size or position.

## API and models
The map itself reads the existing `GET /api/v1/tables/:id` (fields and records) through `useTable`, so a failed load shows the Collection page's existing error. Nothing is written from the map; coordinates and addresses are edited in the Grid view, and failures there show the existing record error.

**Geocoding (addresses).** The table endpoints (`GET /api/v1/tables/:id` and every field/record call, which answer with the whole table) now also return:
- `fields[].geocode`: boolean, set with `POST/PATCH /api/v1/tables/:id/fields` (`field: { geocode: true }`). Only a `text` field can have it (otherwise 422, "Place lookup is only available on text fields"). Turning it off clears the stored places of that field; the text stays.
- `records[].places`: by field id, what the place search made of the cell's text: `{ "status": "found", "latitude", "longitude", "name" }`, `{ "status": "not_found" }`, or `{ "status": "failed", "error": "..." }`. Empty `{}` when nothing was looked up.
- `geocoding`: boolean, whether the server has a provider configured (the web app only offers the option then).

A record save (`POST/PATCH .../records`) writes the typed text first, then, outside the table lock, looks up each saved cell of an opted-in field (`Geocoding::Locator`) and stores the outcome on the cell. A failed or empty lookup never fails the save and never changes the text. Models and tables: `table_fields.geocode` (boolean), `table_cells.geocode` (json, cleared by `TableCell` whenever its value changes), `geocoded_places` (the per-Space cache: `workspace_id`, `provider`, normalised `query`, `latitude`, `longitude`, `display_name`; unique on those three; removed with the Space). Code: `backend/app/services/geocoding.rb` (the seam: `Geocoding.provider`, `Geocoding.enabled?`), `geocoding/nominatim.rb` (the one adapter built), `geocoding/null_provider.rb` (the default; never makes a request), `geocoding/coordinates.rb` (the Ruby twin of `parseCoordinates`; keep them in step), `geocoding/locator.rb`. Lookups use an `open_timeout` of 3 s and a `read_timeout` of 5 s; a lookup that takes long delays that save's response (a request is not queued in a job). Copying a Collection to another Space (`SpaceTransfer`) keeps the setting and the stored places. Configuration and privacy: [services.md](../services.md).

## Who can view and change
Anyone who can open the Collection can use the map; it changes nothing. Editing locations, switching address lookup on or off, and saving a record (which is what sends text to the provider) follow the Grid view's existing permissions (members of the Space with write access). Cached lookups belong to one Space and are never used for another.

## Web entry points
`/documents/:id` for a Collection (`components/editors/TableEditor.tsx`), then **Map**. Code: `components/editors/CollectionMap.tsx` and `.scss`; pure logic in `util/geo.ts` (coordinates, Web Mercator projection, fit, pan, zoom, tiles, graticule) and `data/location.ts` (location fields, pins, labels, details); `hooks/useElementSize.ts`. The option and each address's result are in `TableEditor.tsx` (`PlaceNote`, the field form); the shared wording is `placeProblem` in `data/location.ts`.

## Known limits
- **Choosing the geocoding provider, and any API key, is Alex's call.** Nothing is chosen, so by default addresses are not turned into coordinates. The Nominatim-compatible adapter needs `GEOCODER_PROVIDER=nominatim` and `GEOCODER_URL` set on the Rails API (see [services.md](../services.md) for variables and privacy: opted-in text leaves the server on every save). The conservative choices built in: it is off unless configured; a field must opt in (a person turns it on per text field); no default server; https is advised but any http(s) URL is accepted; no API key is required; failures are not retried automatically and not cached.
- Turning the option on does not look up the records already saved; their addresses are looked up when each is next edited (`docs/backlog/geocode-existing-collection-records.md`).
- A lookup runs inside the save request, so a slow provider slows that save (at most about 8 seconds per address, one address per opted-in field in the record). A job queue and a retry are not built.
- A "location" field type, a lat/lng pair of number fields and a coordinate picker are not built; the map reads a text field so it does not depend on the unmerged `collection-field-types` and `contact-location-and-link-fields` branches (those branches' `location` type was not used: it is not on main). When a `location` type lands, add it to `locationFields` in `data/location.ts`, and give it the same stored `places`/opt-in instead of the text-field flag.
- Only the first match is used, with no way to pick another or to correct a pin by hand (type coordinates instead). A match is as good as the provider's data; a vague address can land somewhere unexpected, and the matched name is shown so it can be checked.
- Cached answers never expire, and the cache is per Space and per provider name, so changing provider looks the text up again.
- No base-map imagery without `MAP_TILE_URL`, and the production Docker build does not pass the two variables through yet (see the Blocked note in the backlog file). Which tile provider to use, and its terms and cost, is Alex's call.
- No clustering: pins that are close together overlap. No pinch or wheel zoom (so the page still scrolls); use the buttons. On a touch screen a drag that starts on the map moves the map, not the page; scroll from the margin or the side panel.
- The view does not wrap across the date line, and the Grid/Map choice and the map position are not remembered or in the URL.
- A Collection with thousands of records lists them all in the side panel; only pins near the screen are drawn.
- The "Open in OpenStreetMap" link sends the record's coordinates to openstreetmap.org only when someone clicks it.
