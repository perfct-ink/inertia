# CSV and Excel import and export

## What it does
- **Export a Collection.** In the Collection editor, **Export** (next to **Import**) opens a menu with **CSV (.csv)** and **Excel (.xlsx)**. The file has a header row (`Record ID` then each field's name) and one row per record, named after the Collection (`Contacts.csv`). Values are written as stored: booleans as true/false, dates as `YYYY-MM-DD`, date and times as UTC ISO text, a relation as the linked record's id, a File field as the file item's id and a Files field as ids separated by `; `. A **formula** field is written as the value it works out to (or its error label such as `#DIV/0!`), calculated in the browser with the same code the grid uses. Export is switched off until the Collection has a field.
- **Export tasks.** On the Tasks page (list or Workboard) **Export** downloads the tasks the current folder, status, epic, sprint, type, assignee filters and search show. Columns: ID, Title, Type, Status (the board's own status names, see [configurable_statuses.md](configurable_statuses.md)), Priority, Assignees (names, separated by `; `), Start date, Due date, Epic, Sprint, Milestone, Document, Estimate (hours), Story points, Description. Switched off when no task is shown.
- **Import records into a Collection.** **Import** opens a dialog: choose a CSV (comma, semicolon or tab separated, UTF-8), TSV or Excel (`.xlsx`) file of up to 5 MB. The first row holds the column names. Each column gets a menu: **Don't import**, one of the Collection's existing fields, or a **new field** of type Text, Integer, Number, Boolean, Date or Date and time. The first guess maps a header that matches a field name (ignoring case) to that field, skips `Record ID` and repeated headers, and makes any other column a new field whose type is guessed from its values (the narrowest type that reads every value; zip codes and ids with leading zeros stay text). The dialog shows a sample value per column and, before anything is sent, lists every bad value as `Row 3, “Age”: “old” is not a whole number` (spreadsheet row numbers, header = row 1); **Import** stays off until there are none. Rows that are empty in the chosen columns are left out and counted. When it succeeds the records are appended, new fields are created and the grid refreshes.
- **Excel files.** Only the first worksheet is read. Dates and times (cells with a date format) come in as `YYYY-MM-DD` / `YYYY-MM-DD HH:MM:SS` (1900 and 1904 date systems), booleans as true/false, formulas as their last calculated value, rich text as plain text. A column of dates where some cells are exactly midnight is still read as Date and time (a bare date counts as midnight). Old binary `.xls` and password-protected files are turned away with a message that says to save as `.xlsx` or CSV.
- **Fields that are not imported into.** Formula fields (calculated) and File/Files fields are not offered as targets, a header that names one is skipped, and the server refuses them. Relation cells take the id of a record in the linked Collection (`12` or `#12`); there is no lookup by name, and relation or file *fields* cannot be created from a column.

## No new dependency
An `.xlsx` is a ZIP of XML parts, so the app reads and writes it itself instead of adding a spreadsheet library (nothing new in `package.json` or the `Gemfile`; decision recorded because the rules say no new tooling without asking):
- `frontend/src/util/zip.ts` writes a ZIP with stored (uncompressed) entries and reads one, inflating compressed entries with the browser's `DecompressionStream('deflate-raw')` (Chrome 80, Safari 16.4, Firefox 113 and later; an older browser says to save the sheet as CSV). It refuses encrypted files and entries that unpack past 20 MB.
- `frontend/src/util/xlsx.ts` builds a one-sheet workbook (text as inline strings, numbers and booleans typed, empty values left empty, bold frozen header row, column widths) and parses the first worksheet with `DOMParser`, up to 50,000 rows and 1,000 columns.
- If a library (for example SheetJS or ExcelJS) is wanted later for several sheets, styles or `.xls`, it would replace those two files only.

## Safe against formula injection
Spreadsheet programs run a cell that starts with `=`, `+`, `-` or `@` as a formula. A CSV export writes such text with a leading apostrophe (`'=cmd()`); an Excel export writes text as text cells, which are never run, so it needs no change. CSV files start with a byte-order mark so Excel reads accents correctly.

## API and models
- `POST /api/v1/tables/:id/import` with `{ columns: [{ field_id } | { name, data_type }], rows: [[...]] }`. Positions in a row follow `columns`; empty cells are `""`. Answers like the other Collection edits (the whole updated Collection) or `422 { errors: ["Row 3, Age: ..."] }`. Everything runs inside the Collection's lock and one transaction, so a bad value anywhere creates no record and no field. At most 1,000 records and 10,000 cells per request (the browser checks the same limits first).
- `app/services/TableCsvImport` does the work: every cell goes through `TableCell`'s own validation (the same rules as a hand-typed record), new field types are limited to text, integer, number, boolean, date and datetime, and formula columns, fields of another Collection and a field named twice are refused.
- No migration. The file itself never reaches the server; the browser reads it and sends typed values.
- Web code: `components/editors/CollectionCsv.tsx` (the buttons and dialog, in `TableEditor`), `components/ExportMenu.tsx` (the Export menu, also used on the Tasks page; `Menu` got `alignEnd`), `data/collectionCsv.ts` (export rows, value conversion, type guessing, column mapping, the import plan), `data/taskCsv.ts` (task export rows), `data/exportFormat.ts`, `util/csv.ts` (read/write CSV, `neutralizeRows`, file names), `util/download.ts` (`downloadRows`, `readTableFile`).

## Who can view and change
Anyone who can open the Collection or the Tasks page can export what they see. Importing needs write access in the Collection's Space (a viewer gets 403, and someone outside the Space 404, from the same checks as every other Collection edit). Nothing about permissions changed.

## Known limits
- Import is for Collections only. Importing tasks and Spreadsheet documents, and exporting Spreadsheet documents, are separate backlog tasks (`docs/backlog/import-tasks-from-csv-or-excel.md`, `docs/backlog/spreadsheet-documents-excel-import-export.md`).
- Records are appended; there is no update-by-id, no "replace the Collection" and no undo (delete the records or fields by hand).
- Excel: first worksheet only, no styles beyond the bold header, no formulas written on export (values only), `.xls` and encrypted files not supported. Dates written as text in another format (`11/01/2026`) are not guessed and fail with a message that names the expected format.
- Numbers keep what the sheet stores (Excel keeps 15 digits); a number shown with a currency or percent format is read as the plain number.
- A File or Files field is exported as file item ids, not file contents.
