## Conventions

- **Match surrounding code.** Keep comment density, naming, and idioms consistent. Comments explain *why*; many files have a header comment worth reading before you edit.
- **No new infrastructure without asking.** The stack is deliberately Rails + MySQL + Solid Cable + Solid Queue (Solid Queue runs inside Puma via `SOLID_QUEUE_IN_PUMA=1`), with no Redis and no separate Yjs or WebSocket server. Keep one root `docker-compose.yml` and one root `Makefile`, and extend them rather than adding per-directory tooling.
- **API shape:** controllers under `Api::V1`, JSON built from models' `as_json`, with the matching TS type in `web/src/types/models.ts` and a client in `web/src/api/<resource>.ts`. Decimals serialize as strings, so parse them on the web side.
- **MySQL JSON columns:** Rails doesn't see MySQL expression defaults on new records. Declare `attribute :x, :json, default: -> { [] }` in the model.
- **Permissions:** most production-scoped mutations are owner-only (`require_owner!`). Budget is available to owners and members explicitly granted the Budgeting role (`budget_access`); only owners can grant or revoke that role. Logistics coordination (schedule, call sheets, locations, equipment, contacts, tasks, media cards, cuts, deliverables, team-library assignments) is available the same way to owners and members granted the production manager role (`production_manager` / `Membership#manages_production?`) — narrower than owner since it doesn't reach creative content or budget. The nav filters by role. Don't loosen a permission as a side effect; call it out.
- **Tiptap:** keep all `@tiptap/*` packages on the same exact version. A caret range on a new extension can pull a conflicting `@tiptap/pm`.
- **Yjs / React:** live script co-editing (`web/src/lib/actionCableYjsProvider.ts` plus `ScriptChannel`) creates the Y.Doc in `useMemo` but connects and disconnects only in `useEffect`. Destroying a memo-created resource in effect cleanup breaks silently under StrictMode. Follow the same allocate-then-connect split for any similar resource.
- **Tests:** add or extend Minitest coverage for backend changes (request tests for endpoints). The web app uses Vitest for pure logic (`npm test`) and Playwright browser smoke tests (`npm run test:e2e`; see web/README.md for the disposable test API setup). For UI changes, verify in a real browser at desktop (1440px) and mobile (375px) widths, and check both screenshots and the console for errors. A throwaway Playwright script in a temp dir works well; don't commit it.
- **Git:** commit only when asked. Pushing to `main` triggers a production deploy, so don't push `main` unless the user asks. The one exception is `backlog/*` branches in backlog mode ([backlog-mode.md](backlog-mode.md)). Keep commit messages descriptive and in the style of `git log`.
- **Large or ambiguous work (outside backlog mode):** propose a scoped first step and confirm it with the user before building.
